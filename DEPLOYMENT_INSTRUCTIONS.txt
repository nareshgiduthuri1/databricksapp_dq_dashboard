--------------------------------------------------------------------------------
1. HOW OBO AUTHENTICATES WITHOUT ANY TOKEN FROM YOU
--------------------------------------------------------------------------------

With OBO, you NEVER need to:
  * Create a Personal Access Token (PAT).
  * Copy or paste any API keys, passwords, or secrets.
  * Store tokens in `.env` or configuration files.

Here is what happens automatically under the hood:
1. You (or any executive / underwriter) open the Databricks App in your browser.
2. Databricks authenticates you via your corporate SSO (Single Sign-On).
3. Databricks Apps gateway AUTOMATICALLY generates an ephemeral OAuth bearer 
   token for your active session and injects it into the incoming request header:
   `X-Forwarded-Access-Token`
4. Our Python code in `obo_auth.py` picks up that header automatically:
   `st.context.headers.get("X-Forwarded-Access-Token")`
5. The app executes queries against your Databricks SQL Warehouse using YOUR 
   identity and privileges.
6. Unity Catalog automatically enforces:
   - Row-Level Security (RLS) based on who is logged in.
   - Column Masking for sensitive PII.
   - Databricks System Audit Logging records queries as run by YOU!

When Alice logs in, it runs as Alice. When Bob logs in, it runs as Bob.
ZERO tokens to manage!

--------------------------------------------------------------------------------
2. SO, WHAT DO YOU ACTUALLY NEED TO CONFIGURE?
--------------------------------------------------------------------------------

Since tokens are 100% automated by Databricks OBO, you only need to configure 
these 2 simple things:

[1] In Databricks Apps UI (When creating the App):
    - Under "Security & Access", make sure "User Identity (On-Behalf-Of)" is 
      enabled (checked by default in Databricks Apps).
    - Under "Resources / Compute", select your Databricks SQL Warehouse.
    - (Optional) In Environment Variables, set your SQL Warehouse ID:
      Key:   DATABRICKS_WAREHOUSE_ID
      Value: <your_16_char_sql_warehouse_id> (e.g. a1b2c3d4e5f6g7h8)

[2] In data_service.py (Lines 384 - 397):
    - Update the catalog, schema, and table names with your real Unity Catalog 
      names in `get_catalog_sample_tables()`:
      ```python
      def get_catalog_sample_tables() -> Dict[str, Dict[str, List[str]]]:
          return {
              "your_real_catalog": {
                  "your_real_schema": ["table_1", "table_2", "table_3"]
              }
          }
      ```

3. STEP-BY-STEP DEPLOYMENT TO DATABRICKS APPS
--------------------------------------------------------------------------------

Step 1: Open your Databricks Workspace in your browser.
Step 2: In the left navigation sidebar, click on "Compute", then select the 
        "Apps" tab (or click "Apps" directly).
Step 3: Click the blue "Create App" button.
Step 4: Configure App Details:
        - App Name: allianz-data-quality-dashboard
        - Description: Project Allianz Data Quality Dashboard with OBO Auth
Step 5: Source Code:
        - Upload all files from this folder directly into the app workspace, 
          OR connect your Git repository.
Step 6: Attach SQL Warehouse:
        - Under "App Resources" or "Compute", select your active SQL Warehouse.
Step 7: Verify OBO is Selected:
        - Under "Security & Access", ensure "User Identity (On-Behalf-Of)" is 
          selected.
Step 8: Click "Deploy".
        - Databricks Apps builds the container, installs dependencies from 
          requirements.txt, and starts Streamlit on port 8000.
        - Click the App URL to open your live dashboard!
